## ⚠️ The finding that matters: self-serving review markup on the homepage

`index.html` carries, inside its `EducationalOrganization` block:

```json
"aggregateRating": { "ratingValue": "5", "reviewCount": "20", … },
"review": [ 4 × { "@type": "Review", "author": …, "reviewBody": … } ]
```

**None of it is visible on the page.** Checked against the rendered body text,
which is 1,011 characters total:

| Claimed in markup | Present in visible page text |
| --- | --- |
| author "Tilla S." | ❌ no |
| author "William E." | ❌ no |
| author "Lucie G." | ❌ no |
| author "Sam W." | ❌ no |
| any review body | ❌ no |
| the 5/5 rating | ❌ no |
| Tutorful (where the 20 reviews live) | ❌ not mentioned |

`reviewCount` claims **20**; **4** are in the markup and **0** on the page.

That is **two** distinct violations of Google's structured data guidelines at
once:

1. **Self-serving reviews.** Google: *"If the entity that's being reviewed
   controls the reviews about itself, their pages that use `LocalBusiness` or
   any other type of `Organization` structured data are ineligible for star
   review feature."* This is `EducationalOrganization` — an `Organization`
   subtype — reviewing itself.
2. **Markup describing content that is not on the page.** Google requires that
   users *"should be able to see the text of the review and associated rating"*.

**Recommendation: remove `aggregateRating` and `review` from `index.html`.**
Flag for removal, not repair — there is no version of this that becomes
compliant while the reviews live on Tutorful and the homepage shows none of
them. It produces no rich result today and carries live manual-action risk.

**This is a content change and I have not made it.** It needs your say-so.

Contained: the sweep found `Review`/`AggregateRating` on **index.html only**.
Nothing else on the site carries either.

## B2 — Eligibility, checked against current documentation

Checked in August 2026 rather than assumed, and **three of the brief's premises
have moved**.

### ❌ `Quiz` / practice problems — the feature no longer exists

The brief asked me to check whether economics is an eligible subject. That
question is now moot: **Google deprecated the practice problems rich result
entirely**, announced November 2025, documentation removed January 2026. It is
gone from Search, from the Rich Results Test and from Search Console reporting —
for every subject and every site.

The 166 practice pages carry `Quiz` with `"eduQuestionType": "Multiple choice"`,
generated from the same JSON as the visible HTML, so it is accurate and matches
the page. Google states leaving deprecated markup in place carries no penalty.

**Recommendation: leave it.** It is correct, it costs nothing, it documents the
page semantically, and removing 166 pages' worth of valid markup to chase a
feature that no longer exists is churn. **Do not expect a rich result from it.**

### ❌ `FAQPage` — deprecated outright, more recently than the brief assumed

The brief says FAQ rich results are "limited to well-known authoritative
government and health sites". That was the September 2023 position. Since then
**Google removed FAQ rich results altogether on 7 May 2026** — Search Console
reporting ended June 2026, API support ends August 2026.

So the conclusion is the same but firmer: **`faq.html` will not produce an FAQ
rich result**, and not because of who runs the site. `FAQPage` remains a valid
schema.org type and unused structured data causes no problem.

**Recommendation: leave it. Add nothing. Expect nothing.**

### ⚠️ Education Q&A (flashcards) — live, but this site is **not** eligible

This is the one feature in the family that **is** still supported (docs updated
January 2026, English included). It needs `Quiz` → `hasPart` → `Question` with
`eduQuestionType: "Flashcard"`, `text` and `acceptedAnswer`.

**But it requires the questions to be visible on the page:** *"the questions
aren't held only in a data file or PDF."*

On this site they are:

| Deck | Cards in deck | Cards visible in the static HTML |
| --- | ---: | ---: |
| Edexcel A Theme 1 | 95 | **3** |
| Edexcel A Theme 2 | 106 | **3** |
| Edexcel A Theme 3 | 97 | **3** |
| Edexcel A Theme 4 | 84 | **3** |
| AQA micro | 185 | **3** |
| AQA macro | 104 | **3** |

Every deck is fetched at runtime from `/flashcards/data/*.json`. Only three
`fc-sample` cards are in the HTML, as a no-JavaScript fallback.

**Recommendation: do not add flashcard markup.** Marking up 95 cards when 3 are
on the page is precisely the "content not visible on the page" violation this
audit just flagged on the homepage. Marking up only the 3 visible ones is
compliant but pointless. The honest prerequisite is rendering the deck into the
HTML, which is a feature decision, not an SEO one.

### ✅ `BreadcrumbList` — the one with real, current value

Still fully supported and still produces a visible SERP feature. It is also the
strongest structural signal in this whole audit for a site whose problem is
that Google has never crawled two sections.

**Recommendation: add it to the 17 pages listed above.** Highest-value item in
Task B by a distance.

### ✅ `Organization` — add `@id` and `logo`

- `logo` is **required** for the Organization rich result and is absent. The
  site has `/og-image.png` and `/android-chrome-512x512.png` to point at.
- A stable `@id` (e.g. `https://economicsacademy.co.uk/#organization`) lets the
  353 nested copies collapse to a reference instead of restating name and url.

**Recommendation: add both.** `sameAs` already points at the Tutorful profile
and is a single string — valid, though an array is more conventional.

### ✅ `Person` — already good, one addition worth making

`about.html` already carries `hasCredential` (First-Class BSc, University of
Bath), `alumniOf` and `worksFor`. It is a genuinely strong E-E-A-T block. It has
**no `@id`**, so the `Person` restated inside `Service` on tutoring.html and
marking.html, and inside `ContactPage`, cannot reference it.

**Recommendation: give it an `@id` and reference it.** The "6 years experience"
in the description is already there.

### ✅ `Service` — already present and complete

Both `tutoring.html` and `marking.html` carry `Service` with `provider` and a
full `offers` array with real prices in GBP. Nothing to do.
